# 0082. cf-purge は 429 の待ちに下限を付け、429 のまま期限に届いたら purge して赤で終わる

- 状態: 採用(0081 の 429 の扱いを上書き)
- 日付: 2026-10-26
- 関連 PR: `fix/cf-purge-retry-after-floor`(本 ADR 起票)
- 関連 ADR: [`ADR 0081`](0081-cf-purge-follow-superseding-build.md)

## 背景

0081 は 429 を「`Retry-After` だけ待ち(上限 300 秒)、回数に数えない」とした。#942 の独立レビューで 2 点が出た(#943)。

- `Retry-After` が 0 や 1 だと、回数に数えないので、期限まで間隔を空けずに API を呼び続ける(写しで builds を 1500 回呼んだ)
- 429 が続いたときの終わり方が段階で違う。script tag の解決中なら「確かめられない」として purge して赤、builds の取得中なら「期限切れ」として purge せずに赤

## 決定

- 429 の待ちは `Retry-After` と通常の間隔(`POLL_INTERVAL`)の長い方にする。上限 300 秒は変えない
- 最後の呼び出しが 429 のまま期限に届いたら、どの段階でも 0081 の「ビルドを確かめられないとき」と同じく、purge して exit 1 にする。最後の呼び出しが 429 でなければ(進行中のまま期限に届いたなど)、0081 のとおり purge せずに赤

## 帰結

- 429 が続く間の呼び出しは、その段階の期限までの秒数を `POLL_INTERVAL` で割った回数を超えない
- 期限を越えうる最大の時間は変わらない(期限の判定 → curl → 429 の待ち → 判定 → purge の順で、0081 の計算に入っている)
