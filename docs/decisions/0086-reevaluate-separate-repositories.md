# 0086. 別リポジトリとコピー持ち込みを続け、CI の共有は別に検討する(ADR 0002 の半年後の再評価)

- 状態: 採用(ADR 0002 の〈コピー持ち込み対象〉〈共通化の判断タイミング〉〈撤回 / 再検討の条件〉を上書き)
- 日付: 2026-11-20
- 関連 PR: (本 ADR と同一 PR)
- 関連 issue: #1035
- 関連 ADR: [ADR 0002](0002-separate-repository.md)

## 背景

ADR 0002 は、edu-evidence と同じリポジトリにまとめず、共通のコードを必要最小限のコピーで持ち込むと決め、
半年運用後(2026-10 頃)に再評価するとした。期限を過ぎても再評価の記録が無かったので、2026-11-19〜20 に、
ファミリーの 5 サイト(公開リポ 4 本と、非公開の履歴を含む 6 リポ)の PR とファイルの履歴を測った。

### ADR 0002 の条件ごとの結果

- **共通コードの重複改修のコストが大きくなっている — 中身が想定と違う。** 下の「重複の中身」のとおり、
  重複の大半は ADR 0002 が想定した共通コード(UI)ではなく、CI・依存・文書だった
- **デザイントークンの差分(色 / フォント / 余白)が頻繁に変わる — 直近は当たらない。** 自リポの `docs/BRAND.md` が
  全サイト共通とするベーストークンのライト値は、作成以来一度も変わっていない。フォントと本文の組版は 2026-05 に
  変えた(ADR 0025・0029)。edu-evidence・edu-watch・edu-law の `src/styles/global.css` への commit は、
  2026-08〜09 は月 1〜4 件、2026-10 以降は 0 件
- **共通の機能要求が複数出る — 当たる。** 検索(Pagefind)・読了バー・トップへ戻る・ダークモード・skip link・
  印刷用 CSS などが、複数のサイトに「移植」「ミラー」として入った。CI でも VRT・E2E・link-check・cf-purge・
  ci-summary・zizmor などが同じ形で入った
- **月 1 回以上、両サイトに同じ修正を二度入れる状態が 3 か月続く — 文字どおりには当たる。** edu-evidence と
  edu-watch の両方に同じ変更を入れた組は、2026-05〜11 の毎月 6〜28 組あった。修正(fix)の組に絞っても、
  2026-08〜10 の 3 か月続けて当たる
- **第三のサイトで 3 リポジトリの並走が破綻する — 判定できない。** 修正が一部のリポにだけ入って取り残された例はある。
  公開リポで、誰でも ci-summary の通知を止められた穴は、edu-watch(2026-10-23)から edu-evidence(2026-11-17)まで
  25 日取り残された

### 重複の中身

同じ変更を 2 つ以上のリポに入れた組は 143 組(2026-05〜2026-11-19。うち edu の公開 3 リポのうち 2 つ以上を含む組は 124)。
UI(レイアウト・スタイル・フォント・ダークモード・OG・favicon)は 22〜27 組で、2026-05 の月 8〜9 組から 2026-11 は
0 組に減った。残りの約 8 割(81〜85%。分類の仕方で振れる)は、CI・テストのガード、依存とランタイム(Node の更新など)、
文書とリポジトリの設定だった。

組は、PR のタイトルの一致・近似と、本文が姉妹リポの PR を引いていることで判定した。タイトルを変えた横展開は
拾えず、参照しただけの PR を拾うこともあるので、数は目安として読む。

### コピー持ち込みしたファイル(2026-11-20 時点)

- `src/data/glossary.ts` と `src/plugins/remark-glossary.mjs` は、edu-watch に一度も入っていない(`git log --all` で 0 件)。
  用語ツールチップのスタイルは `global.css` に持ち込まれたまま残っている
- `src/layouts/Layout.astro`・`src/styles/global.css`・`src/lib/og-image.ts` は、edu-evidence との diff が
  それぞれ 638 行・592 行・182 行あり、サイトごとに分かれている
- `public/_headers`(セキュリティヘッダー)は、edu-evidence と同じ中身のまま

## 検討した選択肢

- **A) モノレポ** — CI・依存・文書の重複も 1 回で済む。ただし、ファミリーには公開と非公開のリポが混ざっている。
  サイトごとに Cloudflare の Worker(とビルド変数 `NODE_VERSION`)・ブランチ保護の required check が分かれている。
  ci-summary と zizmor の workflow は、テストがリポごとに全体を写しで固定している。edu 系の公開 3 サイト
  (edu-evidence・edu-watch・edu-law)だけをまとめる形でも、Workers Builds がモノレポのサイト別ビルドに対応するかは
  確かめていない
- **B) 別リポジトリとコピー持ち込みを続ける(ADR 0002 のまま)**
- **C) UI の npm パッケージ(GitHub Packages)** — 減らせるのは UI の組だけで、それは減りつつある。分かれたファイルは、
  先にサイトごとの差を引数に出す作業が要る
- **D) CI の共有(reusable workflow・composite action など)** — 重複の大半に当たる。ただし、写しで固定するテストや
  リポごとの調整と衝突しうる。必要な作業と効果をまだ測っていない

## 決定

B を続ける。ADR 0002 が比べたモノレポ(A)と UI のパッケージ(C)は、いまの重複の中身(大半が CI・依存・文書)と
合っていない。D は効果が見込めるが、本 ADR では決めず、別の issue で検討する。

ADR 0002 の次の節を上書きする。

- **§コピー持ち込み対象**: edu-watch に持ち込んだのは `Layout.astro`・`global.css`・`og-image.ts`・`public/_headers` で、
  glossary の 2 ファイルは持ち込んでいない。ファイル単位の同期はしない。UI/UX は、これまでどおり
  `docs/edu-evidence-parity.md` の表に沿って、機能の単位で edu-evidence にそろえる(parity 文書は有効)
- **§共通化の判断タイミング**: 半年後に 1 回だけ行う再評価は、本 ADR で実施した
- **§撤回 / 再検討の条件**: 3 項目すべてを、本 ADR の「撤回 / 再検討の条件」で置き換える。「月 1 回以上、同じ修正を
  二度…3 か月」は、CI の横展開で常に当たるので判定に使わない

`docs/BRAND.md` の「サイト数が 5 つを超えた段階で、共有 npm パッケージ化を検討」は、ブランドの資産についての別の条件で、
本 ADR とは矛盾しない。

## 帰結

- 移行の作業は発生しない
- 同じ修正を各リポに入れる手間は続く。大半は CI・依存・文書
- 修正が一部のリポに取り残される危険は、D を決めるまで残る(上の 25 日の例)
- 将来 UI を共有するなら、分かれたファイルの差を先に突き合わせる必要がある

## 撤回 / 再検討の条件

点検は D の issue で行い、その issue を閉じるときに下の条件を見直す。

- D の検討で CI を共有すると決めたとき(その ADR で本 ADR との関係を書く)
- あるリポで、セキュリティの修正(GHSA を直す・zizmor の指摘を直す・`public/_headers` を変える・公開リポで第三者が
  workflow の動作を変えられる穴を塞ぐ)の PR をマージし、同じファイルを持つ姉妹リポで同等の PR が 7 日以内に
  マージされなかったとき
- edu-evidence と edu-watch で、`src/layouts/`・`src/styles/` を変える同じ題の PR が、3 か月続けて毎月 1 本以上
  入ったとき(`git log` で数えられる)
- ファミリーの公開範囲や、サイトごとのデプロイの構成が変わったとき
